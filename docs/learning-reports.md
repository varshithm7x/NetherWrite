# Forge learning reports

Learning reports are snapshots of the selected note's saved, locked quiz selections. The application computes counts, answered-only accuracy and topic priorities; the AI never supplies scores. Unanswered questions are excluded from accuracy and keep their answer feedback hidden. Ordinary comments and other notes are excluded. Topics with fewer than three answered questions are labeled as limited evidence.

Reports use the existing vault-local data bridge and atomic writes to `.netherwrite/forge-reports.json` (schema version 1). A report includes question IDs, comment IDs, selected/correct options, explanations, computed statistics, advice and any validated video metadata. Reopening a saved report requires no AI request. Regeneration creates a separate snapshot; deletion only removes the report. App-managed note/directory renames update source references while preserving the recorded scores. A deleted source does not delete its reports. Invalid records are skipped and preserved; unreadable or unsupported libraries are never replaced.

## AI data flow

Explicit report generation sends bounded selected-note content, the computed summary, actual topic names and a bounded set of answer examples (wrong answers first) to the existing configured AI provider. It does not send vault paths, unrelated notes, comment author profiles or raw provider responses. The request budget includes both note and quiz evidence; partial advice coverage is disclosed. First-answer results are not attempt history. The AI receives the note as untrusted reference data. Advice must reference actual topic classifications and quote exact supplied note passages. Its text is rendered as text, with no HTML execution. Semantic quality of the advice still requires human review.

AI errors, missing configuration, invalid output or a 45-second advice timeout leave a usable deterministic report. Explicit cancellation, a changed source/vault or changed saved answers prevent publication. Persistence must complete before the report is shown as saved.

## Connect YouTube discovery

Forge → Reports now includes **Connect YouTube**. Create a personal Google Cloud API key for a project with [YouTube Data API v3 enabled](https://developers.google.com/youtube/v3/getting-started), restrict its API access to that API, and enter it in the app's password field. The key is encrypted using Electron safeStorage in the application profile, following the existing Drive credential convention. Linux's plaintext fallback is refused. The key is never returned through IPC, stored in report artifacts or logs, or bundled into the app. Saving a key does not verify access or spend API quota; authentication and quota failures are reported during discovery. Remove YouTube Key deletes the saved credential without deleting reports.

**Include YouTube recommendations** defaults off. The form shows the exact concise topic queries before generation. Enabling the checkbox and generating authorizes those queries for that report only; the adapter cannot substitute newly changed topics. YouTube receives those queries and the user's API key, but no note contents, vault paths, note identities, quiz answers or scores. This uses the user's Google API quota and no NetherWrite backend. Do not put secrets or personal information in topic labels; leave discovery off for private topics. Missing keys or discovery failures preserve the deterministic report.

The recommendation checkbox is a preference and remains selectable before a key is saved; it locks only while a report is generating. Saving credentials and performing searches still require secure system storage. The discovery adapter rechecks native connection status before sending any query. Missing credentials produce a usable report with a setup message, without a search request. With no eligible weak topics, no video search is made. Save YouTube Key reads the displayed password field even if autofill did not trigger a React change event; Enter saves the key instead of submitting the report form. Refresh YouTube connection rechecks local status without searching. Stale status responses cannot undo a successful key save or reset the chosen preference.

Electron main invokes only the supported [YouTube Data API v3 search endpoint](https://developers.google.com/youtube/v3/docs/search/list), with `part=snippet`, `type=video` and a three-result request limit. The narrow preload surface exposes status, key save/removal, search and cancellation, restricted to the owning main frame. It accepts no arbitrary endpoint, rejects unsafe query strings and sanitizes all returned fields and errors. The native timeout is 6.5 seconds; the report's overall discovery budget is eight seconds. There is no HTML scraping, silent paid service, shared API key, autoplay, player, download or transcript retrieval.

The adapter limits discovery to three priority topics, two videos per topic and six total, deduplicates IDs, and validates canonical watch URLs and HTTPS YouTube thumbnail hosts. Thumbnail URLs come from the discovery response, with a fallback when absent or broken. Tests inject deterministic provider-shaped metadata; fixtures are not production recommendations.

Reopening a saved report uses stored video metadata without discovery. Visible thumbnails make external image requests to YouTube's image hosts with no referrer. Clicking a validated video uses the existing external-link bridge. Previously saved reports retain their old unavailable-video snapshot; generate a new report with discovery enabled to add recommendations.

Manual visual QA and live provider/discovery verification remain the user's responsibility; automated tests use isolated fixtures and mocks.

## Updating a running development session

Reports add `forge-reports.json` to the Electron main process's permitted atomic data files. Vite hot reload updates the renderer but not the existing main-process handlers. After adding Reports or YouTube discovery, stop the old development session, fully close NetherWrite, and run `npm run dev` again so Electron compiles and registers the updated handlers and preload API. An installed application needs a build containing these changes. Save and discovery errors identify older handlers without downgrading to a non-atomic write or changing quiz answers. A "No handler registered for youtube:status/saveKey" error confirms that the running Electron process lacks the new registration; rebuilding files and reloading the renderer alone cannot update it. Fully quit the app and stop/restart the development command.
